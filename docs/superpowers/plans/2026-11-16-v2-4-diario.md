# v2.4 Diário — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (execução direta, fluxo aceito pelo Alex) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** nota privada por partida (dois lados + etiquetas + itens que faltaram), perfil com abas (Partidas / Quem joga comigo / Diário) e resumo filtrável com setas de evolução.

**Architecture:** regras puras em `lib/diary.ts`; tabela `match_notes` com RLS por dono; leitura e escrita com o **cliente da sessão** (`lib/notes-data.ts`); rota `PUT/DELETE /match/[id]/note`; editor cliente na tela da partida; páginas `/player/[id]`, `/player/[id]/parceiros` e `/player/[id]/diario` com um componente comum de banner + abas.

**Tech Stack:** Next 16 (App Router, `cacheComponents`), Supabase (RLS), Vitest.

**Spec:** `docs/superpowers/specs/2026-11-16-v2-4-diario-design.md`

## Global Constraints

- Texto ≤ 2.000; etiquetas ≤ 12 por lado, cada uma com 1–30 caracteres; itens ≤ 6, motivo ≤ 300; `?partidas=` ≤ 100 IDs; tolerância da seta = 5 pontos percentuais; sem setas se o período anterior tem < 3 notas ou o período é "tudo" ou há partidas escolhidas.
- Etiquetas fixas: `Fase de rotas`, `Farm`, `Mortes evitáveis`, `Posicionamento`, `Lutas em equipe`, `Visão`, `Objetivos`, `Rotações`.
- Nota e notas: **só com o cliente da sessão** (`createClient` de `lib/supabase/server.ts`), nunca com o admin. `account_id` vem dos claims, nunca do corpo.
- Tabela nova com RLS e cada política explicada na migração; nada para `anon`.
- A página nunca chama a OpenDota para notas; a aba de parceiros mantém as regras da v2.3.
- **Sem emoji na interface** [Alex: entrega que foi feito por IA e desmerece o projeto]. Ícones só da lucide (traço fino) ou texto puro.
- Lado (Radiant/Dire) nunca com as cores de vitória/derrota. Textos em português.
- `npm test`, `npx tsc --noEmit` e `npm run lint` limpos a cada commit.

## Review Focus

1. **Outra conta tentando ler/editar/apagar a nota** (inclusive pela API REST com a própria sessão) → bloqueado pelo RLS. Teste SQL com dois `auth.uid()` em transação desfeita (Task 2) + teste da rota que ignora `account_id` do corpo (Task 3).
2. **Nota numa partida em que o visitante não jogou** → 403 sem gravar. Teste em `tests/note-route.test.ts`.
3. **Corpo malicioso/enorme** (texto de 10 KB, 50 etiquetas, item inexistente, etiqueta igual nos dois lados, tipos errados) → 400 ou normalizado, nunca 500. Testes de `parseNoteInput`.
4. **Hidratação/fuso nas datas do resumo** → rótulos calculados no servidor com fuso de São Paulo; período usa `nowMs` do servidor. Teste de `selectNotes` em fronteira de dia.
5. **Visitante (deslogado ou outra conta) abrindo `/player/<id>/diario`** → 404, sem ler notas. Verificação no Chrome + teste da função de acesso (`canSeeDiary`).

### Task 1: Regras puras do diário (`lib/diary.ts`)

```ts
export const DEFAULT_TAGS: readonly string[];

export type NoteInput = { goodTags: string[]; badTags: string[]; goodText: string; badText: string; missingItems: MissingItem[] };

export function tagKey(tag: string): string;                       // minúsculas, sem acentos

  { ok: true; note: NoteInput; empty: boolean } | { ok: false; error: string };
export type Period = 7 | 30 | 90 | "tudo";
export type DiaryFilter = { period: Period; heroId: number | null; matchIds: number[] | null };
export function parseDiaryFilter(sp: Record<string, string | string[] | undefined>): DiaryFilter; // padrão 30, inválido = padrão
export function selectNotes(notes: Note[], f: DiaryFilter, nowMs: number): { current: Note[]; previous: Note[] | null };
export type Trend = "up" | "down" | "same" | "new" | null;
export type TagStat = { tag: string; count: number; wins: number; decided: number; trend: Trend; before: { count: number; total: number } | null;
  texts: { matchId: number; heroId: number; won: boolean | null; playedAt: string; text: string }[] };
export type ItemStat = { itemId: number; count: number; reasons: string[] };
export type DiarySummary = { total: number; wins: number; losses: number; good: TagStat[]; bad: TagStat[]; items: ItemStat[] };
export function summarize(current: Note[], previous: Note[] | null): DiarySummary;
export function heroOptions(notes: Note[]): { heroId: number; count: number }[];
```
